## Findings that determine experiment comparability

1. **`cka_loss_layers=-1` disables decoder-state CKA.** It does not mean the last decoder layer. This is explicit in `_get_cka_layer_specs` in `llava/model/language_model/llava_llama.py`, and in both recovered source trees. The named `qwen-7b-cka-grad` stage-2 checkpoint and the current Vicuna `scripts/v1_5/7b/finetune.sh` therefore specify projector-only CKA even though both coefficients are nonzero. A controlled Full or Final-only run must use the symbolic `final` layer, whose depth is resolved from the actual decoder.
2. **The available Vicuna-7B and Qwen2.5-3B stage-1 adapters are CE-only.** Their saved `config.json` explicitly has `cka_loss=false`. They cannot silently stand in for the structurally regularized stage-1 initialization required by the task. No structurally regularized stage-1 adapter for these two priority backbones was found under `checkpoints/`. Supply a verified structural adapter explicitly or train a new shared structural stage-1 adapter, then use that identical adapter for all stage-2 variants.
3. **Qwen2.5-7B has one documented structural stage-1 candidate:** `checkpoints/qwen-7b-cka-grad/llava-pretrain/mm_projector.bin`. Its projector is `mlp2x_gelu`, projector coefficient is `1.0`, tolerance is `0.0`, hidden layers are `[-1]` (disabled), and stage-1 used asymmetric PCGrad, norm caps, and projector-only gradient application. It is a valid fixed structural initialization candidate for a newly trained four-cell stage-2 factorial; its stage-1 controller is part of its recorded provenance.
4. **A historical Qwen2.5-7B Final-only checkpoint exists**, but it is not automatically a controlled comparator: `checkpoints/qwen-7b-cka-lastonly/llava-finetune`. Its saved configuration enables `final`, with projector weight `0` and final weight `0.1`. Its exact source, reference features, initial adapter, and training command need verification before reuse.
5. **Recovered historical hidden CKA differs from the current reference definition.** `recovery/g7az8alq-source/llava/model/language_model/llava_llama.py::_compute_cka_chain_losses` and the recovered Qwen forward start from `inputs_embeds.detach()` (projected `Z`) and then compare each selected state against the previous detached state. The current implementation's `_compute_cka_reference_losses` uses a common detached raw vision reference by default. A saved configuration with `cka_loss_layers=["final"]` alone does not prove that its checkpoint used `CKA(V.detach(), H_final)`. This is a reference change, not an epsilon change. Retrain the factorial under the current audited definition unless source provenance proves a match.
6. **Historical metadata conflicts prevent automatic reuse.** The saved Qwen7 `cka-grad` stage-2 configuration reports PCGrad and norm caps off, whereas `recovery/g7az8alq-source/provenance/wandb-g7az8alq/config.yaml` records them on. Saved training-argument metadata reports batch size 8 and gradient checkpointing on; recovered W&B arguments report batch size 4 and gradient checkpointing off. Those records cannot establish a single matched recipe.

There is no verified Baseline/Proj/Final/Full checkpoint quartet for Vicuna-7B, Qwen2.5-3B, or Qwen2.5-7B. Preserve historical results, mark their comparability unverified, and train new matched cells. No benchmark conclusion about two-location superiority follows from this audit.

## Actual implementation and gradient flow

Entrypoint: `llava/train/train_mem.py` calls `llava/train/train.py`. Model arguments and training arguments are defined in `train.py`; shared image/projector preparation is in `llava/model/llava_arch.py`. Vicuna uses `llava/model/language_model/llava_llama.py`. Qwen uses `llava/model/language_model/llava_qwen.py`, which reuses the Llama CKA helpers; additional backbones use `llava_modern.py`. The trainer in `llava/train/llava_trainer.py` combines the separately weighted model outputs. The optional gradient controller is in `llava/train/vsp_gradient_controller.py`.

The standard CLIP tower is `openai/clip-vit-large-patch14-336`. `CLIPVisionTower.load_model` sets `requires_grad_(False)` and `forward` is decorated with `torch.no_grad()`. `mm_vision_select_layer=-2` and `mm_vision_select_feature=patch` exclude the class token and retain all 24 by 24 = 576 patch features. `L_proj` detaches only the vision reference; projector output remains differentiable. The final reference buffer is likewise detached. `_compute_cka_reference_losses` detaches the reference, gathers the live decoder image states, and does not detach their path through decoder or projector. With full stage-2 tuning, `L_final` therefore reaches decoder and projector parameters. It has no path to the frozen vision encoder or the final RMSNorm/LM-head parameters downstream of the captured state.

The final state is captured with a **forward pre-hook on `model.norm`**, after the last decoder block and before final normalization, for Llama/Vicuna, Qwen, and the shared modern forward. Transformers' `hidden_states[-1]` normally describes the normalized output; the audited code has a fallback to that value when the hook is unavailable. The new controlled runner must use supported backbones and validate that the pre-hook captures the state; a normalized fallback must not silently be called pre-normalization CKA.

By default, stage-2 does not set `freeze_backbone`, `tune_mm_mlp_adapter`, `freeze_mm_mlp_adapter`, or LoRA. Decoder, token embeddings/LM head, and projector train under the language-model objective; vision stays frozen. Stage-1 sets `tune_mm_mlp_adapter=True` and freezes the remainder, training only the projector. `initialize_vision_modules` loads the explicit stage-1 `mm_projector.bin` into the projector. The language backbone is loaded from the designated pretrained model, not from a stage-2 variant. `train.py` calls `transformers.set_seed(training_args.seed)` before model/projector/LoRA initialization.

With gradient rewriting disabled, the trainer uses

`L_total = L_LM + lambda_proj * L_proj + lambda_final * L_final`.

The model returns `loss=L_LM`, weighted `projector_cka_loss`, and weighted `aux_losses`; calling the model's `loss.backward()` directly would omit the regularizers. `LLaVATrainer.training_step` sums those terms. Zero-weighted terms are dropped by the trainer, and the forward skips projector CKA or hidden hooks when the corresponding coefficient is zero. Asymmetric PCGrad, `vsp_apply_to_projector_only`, norm caps, legacy PCGrad, and protected-CKA variants change the gradient protocol and must be held off across the controlled factorial unless the experiment explicitly studies them.

## Exact original numerical objective

Before these ablation changes, `compute_linear_cka_loss` and `_compute_masked_linear_cka_loss` implement the same stabilized centered linear CKA for ordinary image batches:

1. Cast features to FP32 and disable autocast for all CKA calculations.
2. Center each feature channel across that image's participating patches.
3. Divide each centered image tensor by its Frobenius norm, clamped at `torch.finfo(float32).tiny`. This is a single scale per image, **not per-token L2 normalization**. It stabilizes the already scale-invariant linear-CKA calculation while retaining relative patch norms.
4. Compute token Gram matrices `K = Xc @ Xc.T`, `G = Yc @ Yc.T`.
5. Set `a = sum(K*G)`, `b = sum(K*K)`, `c = sum(G*G)`.
6. Compute `s = clamp(a / sqrt(clamp(b*c, min=1e-8)), 0, 1)`.
7. Reduce `mean(relu(1 - tau - s))`, where `tau=0.0` in the standard recipes. ReLU gives zero gradient at the hinge boundary. Do not replace this with an additive epsilon or a different denominator floor without reporting the numerical change.

At `tau=0`, this is the task's `1-CKA` in its supported range. Degenerate centered features have similarity zero and loss one in the unmasked helper. The masked final helper excludes rows with fewer than two marked image tokens; if none qualify, it returns a graph-connected zero. The optional implementation added for this package, `cka_loss_geometry=row_normalized`, applies per-token L2 normalization in FP32 with a row-norm floor `eps=1e-12` **before centering**, then uses the same Frobenius scaling, Gram calculation, denominator floor `1e-8`, similarity clamp, hinge, and reductions. Both projector and final locations honor the same geometry flag. The default remains `linear`; no legacy numerical default or protocol was changed. Protected stage-1/stage-2 modes reject the row-normalized option instead of silently using a different geometry. This is an explicitly named geometry ablation. The older `selected_state_cka.py` helper uses a different filtering/reduction protocol and is not the objective for this factorial.

Projector CKA treats the `(B, patches, vision/projected dimension)` tensor independently per encoded image/crop and averages those similarities. **This includes dummy zero-pixel images supplied for text-only samples:** `LazySupervisedDataset` supplies a zero image whenever an example lacks an image but the dataset is multimodal, and `encode_images` computes projector CKA before checking image-token placeholders. CLIP encodes those pixels into patch features, so projector regularization may contribute on a text-only batch. This existing behavior is retained and cannot be described as averaging only real image-containing examples.

Final CKA gathers marked image-token positions for each example, excludes text and sequence padding, centers each example's marked features separately, and averages examples with at least two marked image tokens. Text-only examples consequently do not enter its mean. For the ordinary single-image `pad` recipe this is an independent per-image mean over eligible examples. For multiple image placeholders/crops per example, projector CKA averages encoded crops, while final CKA pools all marked image tokens belonging to that sequence into one Gram calculation; the feature mask does not track separate image boundaries. The strict per-image claim is therefore restricted to the existing one-image-per-sequence recipe, not arbitrary multi-image/any-resolution inputs. Flat patch merging keeps raw-reference alignment; spatial/unpad merging rejects raw-vision hidden CKA.

Pixel preprocessing padding **does enter both structural losses**. `LazySupervisedDataset` expands rectangular images into squares using CLIP's mean-color background, then runs CLIP preprocessing. No validity mask distinguishes real-image patches from those padding patches. The final image-token mask excludes text and sequence padding only. With tokenizer truncation at 2048, final CKA uses image tokens that survive sequence truncation, while projector CKA is computed before truncation. Keep this behavior fixed in all controlled cells and report it; removing pixel padding would be an additional method change.

## Required interpretation of the new experiments

Train all four primary variants from the same per-backbone pretrained language model and verified structural stage-1 adapter, at coefficients `(0,0)`, `(0.1,0)`, `(0,0.1)`, and `(0.1,0.1)`. Use common seeds (prefer 42, 43, 44) and record every pending/failed/completed run; independent seeds concern stage-2 training conditional on the fixed stage-1 adapter. The Full and Final configurations must select only `final`, without a teacher adapter, auxiliary inference head, attention selection, Otsu, intermediate objectives, or hidden/vision-anchor overrides.

Measure separate weighted projector/final/combined regularizer gradients reaching the projector on the same representative training batches at the same initialization. Characterize both whole-model and projector-only norms; report norm distributions and the non-additivity of combined gradient vectors. A scalar projector coefficient can approximate a chosen norm statistic but cannot reproduce Full's gradient direction or its decoder parameter support. Keep calibration apart from benchmark testing and keep training steps/global batch fixed.

The audit supports implementing new controlled experiments. It does **not** empirically establish that Full beats Final-only, stronger projector regularization, or row-normalized CKA, that gains generalize across backbones/seeds, which benchmarks improve/regress, or whether added training cost is justified. Those six questions remain pending new comparable training and evaluation results.
